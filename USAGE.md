# Инструкция по использованию img2stl

Приложение: одна фотография → готовая к 3D-печати модель (STL/OBJ/3MF).
Всё исполняется локально в контейнере; UI — `http://127.0.0.1:7860`.

## Запуск и остановка UI

```bash
cd pic2stl
scripts/run.sh          # запуск → http://127.0.0.1:7860
```

Остановка: `Ctrl+C` в терминале, где работает `run.sh`, либо `podman stop img2stl`.

Первый запуск после чистой установки качает ~6 ГБ весов в volume `img2stl-cache`
(10–15 мин); далее — офлайн. Подробнее про установку — `DEPLOY.md`.

## Генерация модели в UI

### Режим «Мультивью (1–4 фото)» — по умолчанию

2–4 ракурса **одного и того же объекта** → модель Hunyuan3D-2mv строит точную
геометрию со всех сторон, включая тыл.

1. Снимите объект спереди/сзади/слева/справа (минимум — один кадр, лучше 2–4):
   камера на уровне центра объекта, вид строго перпендикулярно стороне,
   одинаковое освещение и дистанция на всех кадрах.
2. Разложите кадры по слотам **Front / Back / Left / Right**.
3. Задайте размер/ось/форматы → **Generate**.

В результате: галерея «после снятия фона» по каждому виду, 3D-превью,
файлы и метрики (в метриках — режим и число видов). Первый мультивью-прогон
скачивает ~2.5–3 ГБ весов 2mv (далее офлайн).

### Режим «Одно фото»

Одиночный кадр → Hunyuan3D-2. Быстрее, но тыл объекта «додумывается» моделью.

### Общие параметры

- **Целевой размер, мм** — размер **по выбранной оси**, пропорции сохраняются.
- **Ось масштабирования** — «макс. габарит» (по умолчанию) или X/Y/Z.
- **Форматы** — STL (по умолчанию), OBJ, 3MF.
- **Дополнительно**: шаги диффузии (10–50), детализация меша/октодерево
  (128–384; 384 = высокая детализация, дольше и больше граней), guidance scale
  (следование фото; 5 — стандарт), Seed (воспроизводимость).

Файлы также появляются на хосте в `out/run_<дата_время>/`.

Типичное время: one-view ~60–80 с; мультивью ~40–60 с (готовые веса).
При повышении octree до 384 — примерно вдвое дольше.

Жёлтое предупреждение «остался не-watertight» — осмотрите модель в слайсере.

## Проверка перед печатью

Откройте STL в слайсере (PrusaSlicer/Cura). Критерий готовности:
- нет предупреждений о не-манифолде;
- габариты соответствуют заданным мм.

## Без UI — одной командой

```bash
# one-view: одиночное фото
scripts/dev.sh python -m img2stl.smoke --img samples/test.png --out out
# мультивью: каталог с видами front/back/left/right (.png/.jpg/.jpeg, 1–4 шт.)
scripts/dev.sh python -m img2stl.smoke --views path/to/views --out out
# опции: --target-mm 60 --steps 30 --octree 256 --seed 0
```

В логе: GPU, тайминги, метрики до/после ремонта; в `out/` — `raw.glb`
(сырой меш) и `final.stl`.

## Разработка

```bash
scripts/dev.sh pytest -q        # юнит-тесты (28)
scripts/dev.sh bash             # shell в контейнере; исходники смонтированы поверх /app
podman build -t img2stl .       # пересборка образа (тяжёлые слои кэшируются)
```

`dev.sh` монтирует живые исходники: тестам и CLI пересборка не нужна,
она нужна только для UI, запускаемого через `run.sh`.

## Обслуживание

| Что | Как |
|---|---|
| Веса (~6 ГБ, volume `img2stl-cache`) | качаются один раз; удалить: `podman volume rm img2stl-cache` |
| Старые результаты | `out/run_*` не чистятся сами (STL по 15–30 МБ) — удалять вручную |
| После обновления драйвера NVIDIA | `nvidia-ctk cdi generate --output=~/.config/cdi/nvidia.yaml` (иначе GPU пропадёт из контейнера) |
| Порт занят | `podman stop img2stl` или `PORT=7861 scripts/run.sh` |
| Место | `podman system df`; образ `img2stl` ~12 ГБ |

## Качество входных фото

Мультивью закрывает главную слабость one-view: **тыл больше не «додумывается»**,
если снят реальным ракурсом. Требования к кадрам те же: объект целиком в кадре,
ровный фон, без бликов, скрывающих форму; плюс — одинаковая дистанция и высота
камеры на всех ракурсах, вид строго перпендикулярно стороне объекта.

Для one-view: фото строго спереди, объект по центру, целиком в кадре.
